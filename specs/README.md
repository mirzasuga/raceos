# OpenSpec — Factory Specifications

> Behavioral contracts generated by the Planning Node.

## Structure

```
specs/
├── README.md           ← You are here
├── templates/          ← Spec templates (Jinja2 rendered)
│   ├── proposal.md     ← Change proposal template
│   ├── design.md       ← Technical design template
│   └── tasks.md        ← Task breakdown template
└── changes/            ← Generated change artifacts (per-task)
    └── <task-name>/
        ├── proposal.md
        ├── design.md
        └── tasks.md
```

## Relationship to Parent openspec/

The parent RaceOS repository has its own `openspec/` at:
```
../openspec/specs/      ← Canonical behavioral specs (read by factory)
../openspec/changes/    ← Change proposals (written by factory planning node)
```

This `specs/` directory is for:
- Factory-specific spec templates
- Local documentation about spec generation

The factory's Planning Node **writes** change proposals to `../openspec/changes/`, NOT here.

## How Specs Flow

```
Brain (.raceos/) ──read──► Planning Node ──generates──► openspec/changes/<task>/
                                                              │
                                                              ▼
                                                     Human Approval Gate
                                                              │
                                                              ▼
                                              Execution (uses spec as contract)
```

## Template Format

Templates use Jinja2 syntax with structured variables:
- `{{ title }}` — task title
- `{{ problem }}` — problem statement
- `{% for criterion in criteria %}` — success criteria loop
- `{% for task in tasks %}` — task breakdown loop
